  - Registrar trazabilidad de cada intento

  - Incluir consultas SQL

Stack obligatorio: Odoo + Python + SQL + APIs + base relacional.


--------------------------------------------------------------------------------
2) ARQUITECTURA QUE VAMOS A ENTREGAR
--------------------------------------------------------------------------------

  Sistema externo
        |
        |  POST /api/v1/orders  (JSON)
        v
  API Python (FastAPI)     ← middleware / integración
        |
        +---> Validaciones (cliente, productos, cantidades, precios, duplicados)
        |
        +---> Odoo 18 (XML-RPC)  → crea partner / sale.order
        |
        +---> PostgreSQL propio  → processed_orders + integration_logs


Por qué un middleware (y no solo un módulo Odoo):
  - Separa el sistema externo de Odoo
  - Facilita validar, loguear y evitar duplicados
  - Es más fácil de explicar y demostrar en una prueba

4) PROBLEMAS QUE TUVIMOS Y CÓMO LOS RESOLVIMOS
--------------------------------------------------------------------------------

PROBLEMA A — Docker decía "Virtualization support not detected"
  Causa:
    La virtualización de la CPU no estaba usable / Docker no podía
    crear su motor Linux.
  Solución:
    En BIOS del Aspire A515-55 (tecla F2 al encender):
      Intel Virtualization Technology = Enabled
      Guardar con F10.

PROBLEMA B — WSL no estaba instalado / sin distribución
  Causa:
    Docker Desktop moderno en Windows necesita WSL2 + una distro Linux.
  Solución:
    En PowerShell como Administrador:
      wsl --install
      wsl --install -d Ubuntu
    Crear usuario Linux (danny) y contraseña.

PROBLEMA C — Postgres marcaba "unhealthy" y Odoo no arrancaba
  Causa:
    El healthcheck usaba: pg_isready -U odoo
    Eso intenta conectar a una base llamada "odoo" (mismo nombre del usuario).
    Esa base todavía no existía.
  Solución:
    Cambiar healthcheck a:
      pg_isready -U odoo -d postgres
    Luego: docker compose up -d

8) CÓMO ESTÁ ARMADA LA API (EXPLICACIÓN PARA LA ENTREVISTA)
--------------------------------------------------------------------------------

Idea: la API es un "middleware". No reemplaza a Odoo; orquesta.

CAPAS (de afuera hacia adentro):

1) app/api/routes_orders.py
   - Endpoints HTTP
   - POST /api/v1/orders
   - GET  /api/v1/orders/{external_order_id}
   - GET  /api/v1/orders/{external_order_id}/logs

2) app/schemas/order.py
   - Valida el JSON de entrada con Pydantic
   - Rechaza quantity <= 0, price < 0, sin líneas, sin email, etc.

3) app/services/order_processor.py
   - Cerebro del negocio:
     a) ¿Ya existe external_order_id? → no duplicar
     b) Buscar/crear cliente en Odoo
     c) Validar SKUs (PROD-001...)
     d) Crear sale.order
     e) Guardar logs de cada paso

4) app/services/odoo_client.py
   - Habla con Odoo por XML-RPC
   - authenticate / search / create partner / product / sale.order
   - Guarda el ID externo en client_order_ref

5) app/db/*
   - PostgreSQL propio (puerto 5433), separado del de Odoo (5432)
   - processed_orders  → estado final / anti-duplicado
   - integration_logs  → trazabilidad paso a paso

POR QUÉ DOS POSTGRES:
  - 5432 = datos de Odoo (clientes, productos, ventas)
  - 5433 = datos de la integración (logs, estados, idempotencia)
  Así no mezclamos responsabilidades y es fácil hacer SQL de análisis.

CÓMO CORRER LA API:
  cd C:\Users\danny\odoo-order-integration
  docker compose up -d

  # Opción A (recomendada en Windows si Activate.ps1 falla):
  .\.venv\Scripts\uvicorn.exe app.main:app --reload --port 8000

  # Opción B (si quieres activar el venv):
  Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
  .\.venv\Scripts\Activate.ps1
  uvicorn app.main:app --reload --port 8000

  Docs automáticas: http://localhost:8000/docs
  Health:          http://localhost:8000/health

PROBLEMA D — "ejecución de scripts está deshabilitada" (Activate.ps1)
  Causa: política de seguridad de PowerShell en Windows.
  Solución rápida: no uses Activate; llama directo:
    .\.venv\Scripts\uvicorn.exe app.main:app --reload --port 8000
  O solo para esa ventana:
    Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass


IMPORTANTE:
  En el archivo .env debe coincidir:
    ODOO_DB=nombre_exacto_de_tu_base_en_Odoo
    ODOO_USER / ODOO_PASSWORD = el login con el que entras a Odoo
